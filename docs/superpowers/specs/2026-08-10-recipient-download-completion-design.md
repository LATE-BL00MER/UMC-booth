# 수령 페이지 다운로드 완료 화면 설계

## 목표

사진 수령 페이지의 저장 동작에서 Web Share API를 제거한다. 사용자가 `사진 저장하기`를 누르면 JPEG 파일 다운로드만 시작하고, 다운로드 호출이 정상적으로 끝난 뒤 별도의 완료 화면을 표시한다.

## 저장 동작

- 저장 파일명은 `umc-photo-booth.jpg`를 유지한다.
- 사진 Blob으로 임시 object URL을 만들고 `download` 속성이 있는 앵커를 클릭한다.
- 앵커 클릭 뒤 다음 이벤트 루프에서 임시 object URL을 해제한다.
- `navigator.canShare()`와 `navigator.share()`는 호출하지 않으며 저장 함수의 `navigator` 의존성도 제거한다.
- 앵커 생성이나 클릭이 예외를 던지면 완료 화면으로 전환하지 않는다. 저장 버튼을 다시 사용할 수 있게 복구한다.

## 완료 화면

다운로드 호출이 정상적으로 끝나면 기존 사진 미리보기 화면 전체를 다음 요소가 있는 완료 화면으로 교체한다.

- 브랜드: `UMC PHOTO BOOTH`
- 완료 문구: `사진을 저장했어요`
- HTTPS 지원 페이지로 이동하는 버튼형 링크: `지원 페이지 바로가기`

완료 화면에는 사진 미리보기, 저장 버튼, 보안 안내 문구를 남기지 않는다. 지원 페이지 링크를 누르면 기존과 동일하게 `join_click` 집계 이벤트를 전송한다. 다운로드 직후에는 기존 `save_intent` 집계 이벤트를 전송한다.

## 테스트

- 저장 함수가 브라우저의 공유 API 지원 여부와 관계없이 다운로드 앵커를 한 번 클릭하는지 검증한다.
- 저장 함수 인터페이스에서 `navigator` 의존성이 제거되었는지 검증한다.
- 다운로드가 끝나면 기존 수령 화면이 사라지고 브랜드, 완료 문구, `지원 페이지 바로가기` 링크만 나타나는지 검증한다.
- 지원 페이지 링크의 주소와 `join_click` 이벤트 전송을 검증한다.
- 다운로드가 예외를 던지면 완료 화면으로 전환하지 않고 저장 버튼이 다시 활성화되는지 검증한다.

## 범위 밖

- 운영체제 갤러리에 직접 쓰기
- 다운로드 완료 여부를 운영체제에서 확인하기
- 지원 페이지 주소 또는 집계 이벤트 형식 변경
